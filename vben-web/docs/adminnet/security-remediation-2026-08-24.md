## 处理原则

1. 不重复添加认证中间件，不修改 Admin.NET 应用启动入口。
2. 高风险服务同时具备登录校验、管理员级别、按钮权限和对象/租户范围校验。
3. 不直接把全局权限切换为“所有未登记接口拒绝”，避免未盘点的字典、下拉和详情接口集体失效；先封堵已确认的危险入口，再通过接口清单和回归测试逐步收紧。
4. 当前微信用户接口本身已明确标注匿名访问，因此 APP Token 暂不允许访问任何受保护的管理接口；未来新增应用端受保护接口时必须使用独立授权策略和白名单。
5. 任何依赖升级都必须通过编译、类型检查、生产构建和对应功能回归。
6. 真实密码不写入后续新文档；Git 历史中的凭据必须按“先轮换、再清理历史”处理。

## 2026-08-24 执行结果

- APP 登录模式不再直接绕过后台权限。当前受保护的 APP 路由白名单为空；未来如增加应用端受保护接口，必须建立独立策略和测试后再放行。
- 动态插件的编译、装载和卸载方法改为私有方法，列表、新增、编辑、删除统一要求超级管理员。更新时按数据库中的插件 Id 和程序集名确定卸载目标，不信任浏览器传入的程序集名。
- LDAP 注入对象已正确保存；前端缺少 SM2 公钥时直接阻止登录和改密，不再退回明文传输。
- 请求层增加单次退出保护和请求 Token 比对；迟到的旧会话 401/失效响应不会擦除刚登录得到的新 Token。退出时也不再构造递归登录地址。
- 仓库中的 MySQL、Redis、日志、事件总线、SSH 示例密码和历史 APIFOX Token 文件已移除或置空。本地数据库连接保存在忽略目录 `.runtime-data/local-settings.ps1`，启动时注入，三服务实测均返回 HTTP 200。
- 前端依赖从 3 个严重、38 个高风险降到只剩 Element Plus 2.8.8 的 1 个中风险。该版本由 VForm 3 兼容链固定，暂不盲升；业务页面禁止把不可信 URL 直接传给 `el-link`，后续升级 VForm 时一并处理。
- SSH.NET 升级到 2026.0.0，BouncyCastle.Cryptography 配套升级到 2.7.0。项目仍保留 net6/net8 多目标，因此还原阶段会出现上游组件不支持 net6 的警告；实际运行和验收目标为 net8.0。
- VForm 3 与 hiprint 仍包含第三方 `eval`，且设计器分包约 2.4 MB、2.8 MB。这是旧模板兼容和 CSP/性能的已知风险，不通过关闭构建警告掩盖。

## 后续接手入口

1. 先阅读本文件和 `active-migration-plan.md` 最后一节，再查看 Git 差异；不得修改旧版 `Web`。
2. 修改认证、权限、租户、同步或删除逻辑时，必须同时增加自动化边界测试，并在隔离数据中核对数据库副作用。
3. 首次交付前修改种子默认密码和 Swagger 管理账号，轮换曾进入 Git 历史的 MySQL、Redis、日志服务密码及历史 Token。
4. 有隔离凭据后再做 LDAP、微信、短信、邮件、MQTT、Office 专项联调；未联调不得标记为完成。

## 2026-08-24 工作台与默认首页权限修复

- 工作台不再无条件请求账号、角色、机构和在线用户接口。账号、角色、机构统计分别受 `sysUser:page`、`sysRole:page`、`sysOrg:list` 控制；在线用户统计仅超级管理员和系统管理员请求。
- 站内信区域仅在当前账号实际拥有 `/dashboard/notice` 路由时加载和显示，快捷入口继续以动态路由为准。
- Admin.NET 用户信息不再写死 `/dashboard/home`。动态菜单加载完成后，优先使用真实授权首页，否则选择第一个可访问叶子菜单；没有任何业务菜单时进入 `/no-access`，不再误入工作台或触发 404。
- 登录、刷新页面和退出后重新登录共用同一首页选择规则，切换账号时会更新用户首页并清理上一账号的动态路由。
- 新增首页选择单元测试，覆盖保留已授权首页、工作台未授权回退、空目录排除、无菜单兜底、外链与动态参数页面排除。完整前端单元测试 38 项、Vben 类型检查、本次文件 ESLint 和生产构建均通过。
