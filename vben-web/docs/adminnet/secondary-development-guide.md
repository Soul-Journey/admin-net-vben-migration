# Admin.NET Vben 二次开发指南

最后更新：2026-08-03

## 开发边界

- 新前端只在 `E:\admin.NET\vben-web\apps\web-antd` 开发。
- 后端在 `E:\admin.NET\Admin.NET` 开发。
- `E:\admin.NET\Web` 是旧版对照项目，永久只读，不能修改任何代码、配置或依赖。
- 新页面优先复用现有 Admin.NET 接口、Vben 请求层、权限和分页工具；不要并行建立第二套登录、权限或菜单体系。

## 新页面的基本结构

一个普通管理页面通常包含三部分：

1. `src/api/<模块>/<实体>.ts`：接口、请求参数和返回类型。
2. `src/views/<模块>/<实体>/index.vue`：查询、表格、编辑弹窗和按钮权限。
3. 后端菜单记录：组件路径对应 `模块/实体/index`，后端菜单适配器只会加载真实存在于 `src/views` 下的 Vue 页面。

接口统一使用 `requestClient`，业务页不直接处理 Admin.NET 的 `code/result/message` 信封，也不自行拼接 Token。分页统一使用 `ADMIN_PAGINATION_PROPS`，保持所有列表页的页码、页大小和跳转体验一致。

## 权限与租户

- 前端按钮使用后端返回的权限码控制显示，例如 `hasAccessByCodes(['order:add'])`。
- 后端接口才是最终安全边界。新增、删除、授权、导出、代码生成等写操作必须在后端鉴权。
- 不要因为页面已经限制角色，就删掉服务端的超级管理员或权限校验。
- 涉及租户的数据结构、参数和请求要保留 `tenantId` 的真实含义，不能把默认 `-1` 硬编码为业务数据。

## 代码生成后的接入方式

1. 优先生成 ZIP，在独立分支中检查 API、页面、字段控件和命名。
2. 选择“写入项目”前确认目标路径不存在；生成器会拒绝覆盖。
3. 生成 Vben 页后，在菜单管理新增菜单并授权测试角色。
4. 运行类型检查、页面操作验收和后端接口验收；确认新增、编辑、删除、状态切换的数据库副作用正确。
5. 复杂业务页面应以生成页为起点再拆分 composable、弹窗或领域组件，不要直接改模板文件。

## 高风险操作规则

- 旧版页面永远不修改。
- 菜单、角色、租户和授权数据不能只看页面效果；每次写入后检查数据库关系是否重复、孤儿或越权。
- 代码生成、数据库迁移和文件生成不能覆盖已有文件；先检查目标路径，再执行，失败时清理临时文件。
- 调用短信、邮件、微信、MQTT、LDAP、Office 等外部服务必须使用测试配置，不把“接口返回成功”当作外部联调成功。

## 提交前检查

1. 后端编译通过。
2. Vben 类型检查和 ESLint 通过。
3. 涉及路由、权限或菜单适配时补充并运行单元测试。
4. 对真实写接口使用隔离测试数据，完成新增、读取、更新、删除和清理闭环。
5. 检查 Git 差异，确认没有 `Web` 目录变更、临时生成文件、令牌、密码或本地连接字符串。
