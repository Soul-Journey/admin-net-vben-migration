# Admin.NET Vben 功能与使用手册

最后更新：2026-08-03

本手册面向系统管理员、租户管理员和普通业务用户。新版 Vben 管理端使用现有 Admin.NET 后端和 MySQL 数据，不需要另外维护一套账号或权限。

## 先了解三个概念

### 租户

租户代表一套相对独立的组织与数据空间。登录时默认租户 `-1` 表示平台默认入口；实际可见菜单、用户和数据仍由后端当前租户上下文决定。平台超级管理员可在租户管理中维护租户，并在确认权限后切换到指定租户查看或处理数据。

### 菜单、按钮与数据范围

- 菜单权限决定左侧是否看得到页面。
- 按钮权限决定页面内能否查询、新增、编辑、删除、导出等。
- 数据范围决定能看到哪些机构或业务数据。

前端隐藏按钮只是一层体验保护，真正的鉴权由后端完成。新增角色时应同时完成菜单授权、按钮授权和数据范围授权。

### 账号类型

- 会员：面向注册或外部业务场景的账号类型。
- 普通账号：一般内部使用人员。
- 系统管理员：可承担系统管理职责，但不等于平台超级管理员。
- 超级管理员：平台高风险能力的唯一入口，例如库表、代码生成、系统更新和全局调度。

账号类型来自后端字典，不是 Vben 页面写死的选项。

## 日常使用流程

1. 使用账号密码或手机号登录。手机号短信依赖后台短信服务配置；没有真实短信配置时不能把它当作已联调功能。
2. 进入工作台后，从左侧菜单进入模块；顶部标签页可以切换已打开页面。
3. 列表页通常按“筛选 -> 查询 -> 操作 -> 刷新”的顺序工作。编辑、删除、状态切换均调用真实后端接口。
4. 角色、菜单、租户、代码生成、数据库管理等页面属于高风险操作，应先确认当前租户与权限。

## 核心模块

### 系统管理

- 账号管理：维护账号、机构、职位、角色、状态、密码和附属资料。
- 角色管理：维护角色，授权菜单、按钮和数据范围。
- 机构与职位：维护组织树与职位，供账号和数据范围使用。
- 个人中心：维护当前账号资料、头像和密码。
- 通知公告：维护公告内容与发布状态。
- 三方账号、LDAP、审批流程：页面、接口和安全边界已经接入；真实效果取决于企业侧账号、目录服务或流程业务配置。

### 平台管理

- 租户管理：维护租户、站点信息和菜单授权。切换租户或进入租管端会刷新身份上下文，不会复制或修改权限记录。
- 菜单管理：维护目录、页面路由、组件路径和按钮权限。新增 Vben 页面菜单时，组件路径填写为“页面目录/实体名/index”，例如 `business/order/index`。
- 参数与字典：维护系统参数、字典类型和值。字典修改会按后端规则刷新缓存。
- 模板、打印、任务调度、系统监控、缓存、行政区划、文件、动态插件、开放接口：均使用原 Admin.NET 后端数据。外部连接、文件存储或第三方平台仍需各自配置。

### 日志与开发工具

- 访问、操作、异常、差异日志：用于排查登录、接口调用与数据变化。
- 库表管理与代码生成：只向超级管理员开放。
- 表单设计：可设计、预览、导入导出 JSON、导出代码和 SFC；原系统没有服务端保存接口，因此离开前应导出 JSON。

## 代码生成：从配置到 Vben 页面

代码生成用于根据已有 Admin.NET 实体和数据库表生成 CRUD 代码。它不是“自动创建表”的工具；实体、表和字段必须已经存在。

1. 以超级管理员进入“开发工具 -> 代码生成”。
2. 选择服务端已配置的数据库和实体，填写业务名称、命名空间、Vben 页面目录。
3. 在字段配置中确认列表列、查询条件、必填项、字典、外键、树选择器、上传和唯一约束。
4. 先使用“代码预览”检查生成内容。预览不写文件。
5. 选择生成方式：
   - 下载 ZIP（Vben 前端 + .NET 后端）
   - 下载 ZIP（仅 Vben 前端）
   - 下载 ZIP（仅 .NET 后端）
   - 写入项目（Vben 前端 + .NET 后端）
   - 写入项目（仅 Vben 前端）
   - 写入项目（仅 .NET 后端）
6. 本地写入只会进入 `vben-web/apps/web-antd` 和受允许的后端命名空间，绝不会写入旧版 `Web`。目标文件一旦已存在会直接拒绝，避免覆盖手工代码。
7. 生成完成后，进入菜单管理手动新增菜单并授权角色，再重新登录或刷新菜单。

当前版本不会自动写入菜单权限树。这是有意保留的人工确认点：菜单、角色和租户关系属于数据库权限数据，不能因为一次代码生成而批量重写。

## 常见问题

### 页面看不到或按钮是灰的

先检查当前角色是否拥有对应菜单和按钮权限，再确认是否在正确租户。不要只通过前端显示状态判断权限是否已经生效。

### 本地代码生成提示目标文件已存在

这是覆盖保护。请改用 ZIP 对比，或先人工评审并迁移已有代码；不要删除现有业务文件来强行生成。

### 切换租户后看起来没有变化

只有账号被授予多个租户且各租户菜单/数据不同，切换后才会有可见变化。当前租户上下文由后端 Token 和菜单接口共同决定。

### 短信、邮件、微信、Office 预览等不能真实使用

这些能力依赖外部账号、密钥、网络或存储服务。项目已保留接口和页面边界，但要在测试环境配置真实凭据后再专项联调。
